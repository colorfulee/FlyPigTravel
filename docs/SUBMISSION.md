## 旅行场景与目标用户

**场景**：高品质酒店 staycation，在本市或周边住一晚的微度假。

**用户**：一二线城市 25-40 岁的人群，包括带娃的家庭、过纪念日的情侣、想独处充电的上班族、闺蜜和带父母出游的子女。

**痛点**：订了好酒店，却只用了一张床。套餐权益看不明白，酒店里有什么好玩的不知道，周边能去哪不清楚，需要预约的项目到店才发现约满了。现在的 OTA 只卖房，不管“住进去之后的这 24 小时”。

## 我做了什么

一句话说需求（或上传一张小红书种草截图），「住进去」会：

1. **选酒店**：基于飞猪实时酒店、万豪酒店与万豪套餐数据，按人群、预算、评分和套餐丰富度排序，直达飞猪预订。
2. **读懂酒店（多模态）**：从套餐名称和卖点、用户评价原文、酒店与套餐图片中挖掘“住客能体验什么”。每条体验都标注依据（套餐权益 / 用户评价 / 图片识别 / 周边数据），模型给出的证据必须能在原文中逐字找到，否则丢弃。
3. **空间分层（空间感知）**：用真实坐标计算周边景点的距离和方位，把体验分为“酒店内 → 步行圈 → 车程圈”，用空间图展示。
4. **完整旅程**：从入住到退房后的半天，排成时间线；自动识别套餐中的延迟退房，调整可用时间窗。
5. **主动服务**：不是问一句答一句，而是按旅程时间轴推送提醒，比如“入住前 2 天：下午茶需要预约”“退房前别忘了……”。
6. **不同用户，不同旅程**：同一家酒店并排生成两种人群的版本（如情侣版 / 亲子版），直接回答命题“如何帮不同用户发现最值得体验的部分”。
7. **待确认清单**：图片推断出来的设施、需要预约的权益，不让模型瞎猜开放时间，而是生成要问酒店的问题和一键复制的前台话术。

**创新点**：

- 把酒店从“住宿商品”变成“旅程目的地”。
- 多模态 + 空间感知 + 主动服务三者结合。
- 用“证据必须出自原文”的校验机制，让模型输出可验证。

## 百炼使用说明（必填）

百炼位于**运行时链路**，是作品的核心：所有理解、识别和生成都由百炼完成。

- 百炼能力 / 模型：通义千问 `qwen-plus`（文本理解与生成），通义千问 VL `qwen-vl-max`（图像理解）
- 调用方式：百炼 API（DashScope OpenAI 兼容接口 `/compatible-mode/v1/chat/completions`）
- 使用环节与输入输出：
  1. 需求解析：一句话需求 → 城市 / 日期 / 人群 / 预算 / 想要的体验（JSON）
  2. 种草截图识别（qwen-vl-max）：截图 → 酒店名 / 城市 / 亮点
  3. 体验挖掘：套餐名称 + 卖点 + 评价原文 → 体验清单及逐字证据（JSON）
  4. 酒店图片理解（qwen-vl-max）：酒店 / 套餐主图 → 可见设施（泳池、景观、下午茶等）
  5. 旅程编排：体验清单 + 空间分层 + 入住/退房时间窗 + 人群 → 时间线与主动提醒（JSON），再由代码校验
- Skill 名称（如有）：飞猪 flyai Skill（`@fly-ai/flyai-cli`：search-hotel / search-marriott-hotel / search-marriott-package / search-poi）
- 其他工具 / 技术栈：Python FastAPI、原生 H5 前端、高德地理编码（可选）、pytest

## 踩坑记录（可选）

- flyai 未配置 Key 时价格会脱敏（如 ¥2xx），排序和预算过滤会失真。代码把脱敏价格识别为“未知”，不参与预算判断。
- 模型容易“脑补”酒店设施，所以加了两道闸：文本体验的证据必须逐字出现在飞猪原文中；图片识别出的设施一律进入待确认清单。
- 旅程编排的输出由代码校验（体验 ID 必须存在、时间必须在入住/退房窗口内），不合格时用确定性排程兜底，保证核心路径稳定可用。
