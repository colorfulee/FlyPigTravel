**项目目标：** 征战 2026 飞猪 AI 旅行创新大赛，核心锁定创新性（40%）、完整度（30%）、市场前景（30%）高分闭环。

---

## 一、 系统架构总览

本系统采用前后端分离架构，核心依赖阿里云大模型服务平台百炼的多模态视觉理解能力及 Agent 智能体编排服务。整体技术链路分为三层：

1. **前端交互层：** 移动端 H5 或微信小程序，负责调用摄像头拍摄/上传景区实景照片，展示 AI 解析结果与飞猪商业化推荐卡片。
2. **智能编排与模型层：** 基于阿里云百炼平台搭建的 Agent，核心调用 `Qwen3-VL-Plus` 多模态视觉模型，实现环境场景解析、空间构图与“黄金机位”推荐。
3. **商业化生态对接层：** 对接飞猪开放平台（FlyAI Skill 全品类出行旅游服务），实现“内容种草 ➔ 玩乐门票/本地旅拍权益下单”的交易转化闭环。

---

## 二、 核心功能模块与技术实现规范

### 1. 多模态视觉与空间感知模块 (Vision Analysis)

利用百炼平台的多模态大模型对用户上传的景区照片进行场景深度解析，识别建筑地标、光影条件及构图结构。

* **接口调用方式：** 建议通过后端代理或百炼 OpenAI 兼容 SDK 调用 `Qwen3-VL-Plus` 模型。
* **请求报文示例：**

```json
{
  "model": "qwen3-vl-plus",
  "messages": [
    {
      "role": "user",
      "content": [
        {"type": "image_url", "image_url": {"url": "https://example.com/scenic_spot.jpg"}},
        {"type": "text", "text": "请分析这张景区照片：1. 识别当前景点/地标名称；2. 评估当前光影与构图；3. 为用户推荐 2 个最佳拍照机位或互动姿势建议。"}
      ]
    }
  ],
  "parameters": {
    "temperature": 0.7,
    "max_tokens": 1024
  }
}
```

### 2. Agent 工作流与智能导游编排 (Agent Workflow)

在百炼智能体控制台中配置专属 Agent 节点，设定其人设为“金牌导游与资深旅拍摄影师”，并挂载旅游业务插件。

| 节点名称 | 技术组件 | 核心职责与输入输出 |
| --- | --- | --- |
| **意图识别节点** | Qwen3.8-Flash | 分析用户输入，判断是纯求助景点历史文化、还是寻找拍照机位、或购买周边权益。 |
| **视觉空间解析节点** | Qwen3-VL-Plus | 解析图像中的视觉元素，输出构图坐标及空间特征。 |
| **业务推荐工具 (Tool)** | FlyAI Skill / 飞猪 API | 根据当前识别的景区名称，动态拉取飞猪平台的当地门票、酒店、同款旅拍套餐。 |

### 3. 前端轻量化 H5 / 小程序界面设计规范

* **UI 风格：** 遵循现代简约美学，使用深色导航侧边栏、卡片式信息流布局，确保在手机端浏览时视觉层级清晰。
* **核心交互流程：**
  1. 用户进入页面 ➔ 点击“拍照/上传现场照片”。
  2. 前端通过 FormData 异步提交图片至后端 API。
  3. 页面展示“AI 正在通过空间感知解析机位...”加载动画（2-3秒）。
  4. 渲染结果页：顶部展示大模型生成的“摄影构图建议+文案”，底部挂载“飞猪专属预订卡片”。

## 四、 参赛完整度防错指南（评审核心检查点）

* **异常兜底机制：** 弱网或大模型响应超时情况下，前端必须有友好重试与 Mock 降级展示，确保评委现场测试 100% 不报错。
* **核心链路指标：** 从用户拍照上传到最终呈现机位推荐与飞猪购买链接，全链路耗时必须控制在 **5 秒以内**。
* **资源合规：** 严格使用阿里云百炼平台新用户 **1 亿 Token 补贴**，在代码库和提交文档中注明依托阿里云底层架构。
