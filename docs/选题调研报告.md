### v2 结论

1. **主选不变，仍是高品质酒店 Staycation**，而且理由更充分：官方问题问的是“酒店内外最值得体验的部分”和“完整旅程”，正好对应 flyai 的酒店、万豪套餐、周边 POI 三类数据。9 个方向里它是数据与命题最贴合、且没有竞品的一个。
2. **方案重心要调整**：官方关注的是**体验发现**和**完整旅程**，不是比价。原方案的“套餐值不值计算器”和“日期雷达”降为辅助，主线改为“入住旅程设计”。
3. 注意“**不同用户**”这几个字：同一家酒店，亲子、情侣、独处、带父母要给出不同的旅程。这是演示时最直观的点题方式。
4. AI 私人讲解员的官方描述写得非常具体，等于给了标准答案，大家会做得很像，#169 已经照着做了。不建议选。

### v2 方案：「住进去」· 高品质酒店入住旅程设计师

一句话：**告诉我你是谁、和谁去、想要什么 → 选出最适合你的那家酒店和套餐，挖出酒店内外最值得体验的东西，排成一段从入住前到退房后的完整旅程。**

| 优先级 | 功能 | 实现与数据来源 |
|---|---|---|
| P0 | **人群画像**：亲子 / 情侣纪念日 / 独处充电 / 闺蜜 / 带父母 | 百炼解析一句话需求 |
| P0 | **酒店与套餐匹配** | `search-hotel`、`search-marriott-hotel`、`search-marriott-package`、`keyword-search "XX 酒店套餐"`，按画像排序 |
| P0 | **酒店内体验挖掘** | 从套餐名和 sellingPoint（下午茶、SPA、亲子乐园、延退）、评价文本 review、酒店主图（Qwen-VL 识别泳池、景观、房型）中抽取“体验清单”。**每条标注来源**：套餐权益 / 用户评价 / 图片推断 / 待确认 |
| P0 | **酒店外体验串联** | `search-poi` 查周边（按经纬度算距离，温泉、市集、博物馆等），`keyword-search` 查同期演出、活动 |
| P0 | **完整旅程时间线** | 入住前（提前预约 SPA/餐厅的提醒）→ 入住日 → 次日 → 退房后半日。**同一酒店生成不同人群版本**，可并排对比 |
| P1 | **待确认清单 + 前台话术** | 数据缺口（如泳池开放时间、儿童俱乐部年龄）不让模型编，自动生成“需向酒店确认”的问题和可直接发送的话术，把数据不足变成一个可信的功能 |
| P1 | 套餐值不值 / 日期价差 | 原 5.3 的计算器和雷达，作为选择阶段的辅助 |
| P1 | 种草截图找同款 | Qwen-VL 识别截图，找到酒店后进入上述流程 |
| P2 | 旅程分享海报 | 通义万相 |

数据缺口提醒：flyai 的酒店返回**没有设施列表**（泳池、SPA、餐厅营业时间等）。这是方案最大的技术风险，W1 必须实测：套餐 sellingPoint、review、`ai-search` 按酒店名查询，能补到什么程度。补不全的就进“待确认清单”，**不要让模型猜**。

演示建议：选一家万豪套餐数据丰富的上海或杭州酒店，现场切换“亲子版 / 纪念日版”两条旅程，再点 `detailUrl` 跳到飞猪下单页。

## 2. 数据底座：flyai 实际能做什么

这是选题的关键约束。数据接口覆盖到哪里，就决定了哪个题能做出“真实可订”的东西。

| 命令 | 能力 | 关键返回字段 |
|---|---|---|
| `search-hotel` | 按目的地/景点附近/日期/星级/床型/价格/排序查酒店 | name, price, score, review, star, decorationTime, interestsPoi, 经纬度, mainPic, detailUrl |
| `search-marriott-hotel` | 万豪集团酒店专搜 | 同上 |
| `search-marriott-package` | **万豪集团酒店套餐商品**（下午茶、房+餐等） | name, brandName, hotelName, price, **sellingPoint**, detailUrl |
| `keyword-search` | 一句话跨品类搜（酒店、**酒店套餐**、机票套餐、门票、演出、赛事） | title, price, tags, star, jumpUrl |
| `ai-search` | 语义搜索（复杂意图） | — |
| `search-poi` | 景点，35 类（温泉、露营、乐园、博物馆……），含门票价 | name, address, ticketInfo, jumpUrl |
| `search-flight` / `search-train` | 机票/火车，支持日期区间、时段、中转、时长、价格 | — |

两点值得注意：

1. **飞猪为万豪单独做了两个命令**。整个 Skill 一共 8 个命令，品牌专属的只有万豪，而且其中一个专门搜“酒店套餐”。这说明酒店套餐和高端酒店是飞猪当前想推的生意，**与 Staycation 命题高度吻合**。
2. **没有讲解内容、外语、签证、支付、租车等专门接口**（SKILL.md 描述里提到签证、邮轮、租车，但 CLI 没有对应命令，只能靠 keyword-search 兜底）。所以 AI 讲解和入境游的核心价值主要靠大模型，飞猪数据只能起辅助作用。
3. 不配 `FLYAI_API_KEY` 时是 trial 模式，**价格会被脱敏**（如 ¥2xx）。比价类功能必须申请 Key。

## 4. 五个方向逐一评估（v1，基于媒体报道的 5 个方向，已被 v2 修订取代）

评分 1-5，“获奖概率”综合考虑评审维度、数据适配、竞争和单人可行性。

| 维度 | Staycation | 目的地探索 | AI 私人讲解 | 入境游 | 开放 |
|---|---|---|---|---|---|
| 飞猪数据适配 | **5**（酒店 + 万豪套餐 + 周边 POI 全覆盖） | 4 | 2（只有 POI/门票） | 3（数据为中文，缺签证/支付） | 视题而定 |
| 与飞猪商业诉求贴合（市场前景） | **5**（酒店套餐 GMV，高端酒店战略） | 3（飞猪“问一问/帮帮”已在做） | 2（离交易远） | 4（政策热，但入境主场在携程） | 3 |
| 创新空间 | 4 | 2（最同质化） | 4（多模态有看点） | 4 | 3 |
| 单人 6 周可行性 | **5** | 5 | 3（事实幻觉难控） | 3（多语言 + 跳转中文页） | 4 |
| 当前竞争 | **低**（0 个专做） | 中（且全网同质化） | 中（已有 1 个像样的） | 低 | **高**（3 对撞车） |
| **获奖概率** | **高** | 低 | 中 | 中高 | 中低 |

### 4.1 目的地探索：不推荐
“输入城市和天数，生成行程”是所有 AI 旅行产品的默认功能，飞猪自己的“问一问”和“飞猪帮帮”早就做了。评委看到会觉得审美疲劳，很难在创新性上拿分。

### 4.2 AI 私人讲解：中
优点是演示效果好（拍照 → 语音讲解）。问题有三个：
- 飞猪数据只能提供景点名和门票，讲解内容 100% 靠模型，**历史事实幻觉**是硬伤；
- 离飞猪的交易链路远，市场前景不好讲；
- #169 已经占了“拍照识景 + 史实标注”这个最显眼的切口。

### 4.3 入境游助手：备选（中高）
- 市场论据最强：2026 年上半年入境外国人 2291.4 万人次，同比增长 20.4%，其中免签占 77.7%；1-7 月境外人员在华消费 2636 亿元，同比增长 27.8%；240 小时过境免签已覆盖 55-57 国。
- 痛点明确：携程观察到的高频痛点是**语言沟通、产品理解、行程衔接、突发处理**。
- 风险：flyai 返回中文数据，`jumpUrl` 跳到中文飞猪页面，**外国人能不能在飞猪完成预订**是评委一定会问的问题。入境游的主场也在 Trip.com。
- 如果选它，建议切细分场景：**240 小时过境免签行程合规规划**，即按入境口岸、允许停留的区域、离境口岸和天数约束来排可行行程。这个场景有硬规则、可校验，比泛泛的“外国人中国攻略”强。

### 4.4 开放命题：不推荐
红海，而且没有命题加持。除非你有非常独特的领域资源。

### 4.5 酒店 Staycation：主推
理由汇总：
1. **数据完全够用**，而且有飞猪特意开放的万豪套餐接口，评委里大概率有酒店业务方；
2. **零专门竞品**，现在入场能占位；
3. **商业闭环最短**：推荐 → 套餐 → `detailUrl` 下单，直接对应飞猪的酒店套餐 GMV。“市场前景”这项最好讲；
4. 需求真实：2026 年暑期飞猪国内酒店间夜量同比增长 66%；县城高星酒店五一预订增长 80%；年轻人“住酒店本身就是目的”的 Staycation 趋势明确；
5. 单人可做，可以做出“确定性计算 + LLM”的扎实架构，不靠堆模型。

## 5. 深度方案：Staycation 方向

### 5.1 真实痛点（Staycation 决策为什么难）

1. **套餐看不懂、算不清**：“豪华房 + 双早 + 双人下午茶 + 延迟退房至 14:00 + 儿童乐园”卖 ¥1,688，到底比单订房贵还是便宜？权益怎么折算？
2. **日期弹性没被利用**：周五住和周日住同一家酒店，价格可能差几百，但用户不会挨个日期去查。
3. **“住进去之后干什么”没人管**：Staycation 的价值是那 24 小时的体验，现在的 OTA 只卖房，不排“入住到退房”的时间线。
4. **灵感和下单是断开的**：在小红书刷到一篇“XX 酒店太出片了”，回到 OTA 要自己搜酒店、比套餐、看日期。

### 5.2 产品定义（v1；主线已按 v2 调整为「住进去」）

**项目暂名：「住一晚」· Staycation 微度假管家**
一句话：**一句话需求或一张种草截图 → 帮你挑出最值的那一晚（哪家、哪个套餐、哪天住），再排好 24 小时怎么过。**

目标用户：一二线城市的 25-40 岁人群，包括情侣、亲子家庭和闺蜜，周末或小长假在本市及 2 小时车程内住一晚。

### 5.3 核心功能（按演示优先级）

| 优先级 | 功能 | 实现要点 | 对应评审维度 |
|---|---|---|---|
| P0 | **意图理解** | “这周末带 5 岁娃，杭州周边 2 小时，预算 1500，想泡温泉不想折腾” → 结构化约束 | 可行性 |
| P0 | **候选召回** | `search-hotel`（目的地、日期、价格、星级）+ `search-marriott-package` + `keyword-search "XX 酒店套餐 温泉 亲子"` + `search-poi`（温泉/乐园周边） | 可行性 |
| P0 | **套餐值不值计算器（核心差异点）** | LLM 只负责把套餐名和 sellingPoint 抽成结构化权益（早餐 ×2、下午茶 ×2、延退 4h……）；**确定性代码**按同酒店单房价和权益参考价计算“权益价值、溢价/节省、每项权益的单价”。参考价能从数据里取的就取，取不到的标注“估算”。 | 创新性 + 可信度 |
| P0 | **日期弹性雷达** | 对同一酒店批量查询未来 2-4 个周末和节假日前后的价格，给出“改住周日晚省 ¥xxx”的结论 | 创新性 + 实用 |
| P0 | **24 小时体验时间线** | 入住 14:00 → 泳池 → 下午茶 → 晚餐 → 早餐 → 延退 → 周边 1 个 POI。按套餐权益和周边 POI 排时间线，生成可分享的卡片 | 场景完整度 |
| P1 | **种草截图找同款** | Qwen-VL 识别小红书或抖音截图里的酒店、房型、卖点 → 找到该酒店并比价 → 推荐同款或平替 | 创新性 / 演示爆点 |
| P1 | **分享海报** | 通义万相生成“我的周末一晚”分享卡（带价格和下单链接） | 传播 / 市场 |
| P2 | 双人决策 | 发给另一半投票，或合并双方偏好 | 加分 |

### 5.4 技术架构（单人可落地）

```
前端（Next.js / React，移动端 H5 优先）
   │
后端编排（Python FastAPI 或 Node）
   ├─ 百炼 Managed Agent（qwen3.x-max / flash）：意图解析、套餐权益抽取、时间线文案
   ├─ Qwen-VL：种草截图解析
   ├─ 通义万相：分享海报
   ├─ flyai CLI（FLYAI_API_KEY）：酒店 / 万豪套餐 / POI / keyword-search
   └─ 确定性引擎：套餐估值、日期价差、时间线可行性校验（营业时间、距离、入住/退房时间）
缓存层：SQLite 缓存 flyai 返回（演示稳定 + 节省额度），保存“演示快照”兜底
```

原则：**LLM 负责理解和表达，事实和数字只来自 flyai 和代码计算**。每个价格都可以点 `detailUrl` 跳转核验。这正是头部竞品强调、评委认可的写法。

## 6. 备选方案速写：入境游 · 240h 过境免签行程规划

- 输入：护照国籍、入境航班/口岸、离境计划、天数、兴趣
- 规则引擎：校验国籍是否适用、口岸是否允许、停留区域（省份范围）、240 小时上限、离境必须前往第三国或地区 → 生成**合规**行程
- flyai：`search-flight`（离境航班）、`search-train`（区域内城际）、`search-hotel`、`search-poi`
- 多语言输出（Qwen 翻译）+ “给司机/前台看的中文卡片”
- 难点：政策规则要人工整理并持续核对；外国人在飞猪下单的链路需要说清楚
